# SpellFire_Plus 全局真相路线图

## 0. 当前结论

当前项目已经完成 CTM native command 与 `Movement.Go` 单点 CTM 自动验证，但还不能直接声称有 Navigation 主体。

真实路线固定为：

```text
MemoryRobot
-> Runtime / Hook / Lua
-> WowRuntime.ObjectManager / WorldState / Movement
-> Hook CTM native command
-> Movement.Go 短距离 CTM 样本
-> Navigation 最小执行
-> RobotManager 接入 Navigation
-> Product 体系
```

当前已解除的阻塞：

```text
Hook 协议已有白名单 ClickToMoveMove。
Hook 侧已能通过主线程桥调用 CGPlayer_C__ClickToMove。
Movement.Go 已消费 Runtime facade CTM 白名单命令。
自动样本已采集到 ClickToMoveTypeRaw=4、Speed=7 和真实位移。
```

当前仍成立的边界：

```text
Navigation 当前仍是 NotImplemented。
Movement.Go 只是单点 CTM，不是路径队列，不做避障，不做卡住恢复。
FaceTo / FaceObject 仍未进入成品能力。
```

因此下一主线是 `Movement.Go 成品语义收口 + Navigation 前置边界`，不是 Product，不是 Quest/Gather/Combat，也不是直接宣称完整导航。

## 1. 事实总表

| 层级 | 当前状态 | 已验证事实 | 不能声称 |
| --- | --- | --- | --- |
| `SpellFire.MemoryRobot` | 成品地基 | 进程、内存、模块、线程、远程库原语已收口 | 不理解 WoW / Hook / Lua / 对象 / 导航 |
| `SpellFire.Hook` | 成品地基，CTM 白名单命令已接入 | 已有进程内桥、命令通道、Lua 主线程执行，`ClickToMoveMove` 已验证调用 `CGPlayer_C__ClickToMove` | 不能通用 native call，不能替代导航 |
| `SpellFire.Runtime` | 成品门面 | 已统一 Preflight / Attach / Status / Lua / Shutdown | 不承载 WoW 业务 |
| `SpellFire.RuntimeHost` | 宿主实现和冒烟壳 | CLI/WPF 通过门面验证 Hook/Lua | 不是业务运行时 |
| `SpellFire.WowRuntime.ObjectManager` | 只读成品 | Me / Target / Objects / Guid / Entry / Kind / Nearby / Nearest | 不写对象，不 Pulse，不接管 wManager |
| `SpellFire.WowRuntime.WorldState` | 成品聚合层 | Phase / Player / MovementState / RuntimeWorldSnapshot | 不规划路线，不执行动作 |
| `SpellFire.WowRuntime.Movement` | 部分成品 | Jump / Forward / Backward / Strafe / Turn / Stop / CTM 诊断 / Go 单点 CTM | `Go` 不是导航，`FaceTo`、`FaceObject` 未完成 |
| `SpellFire.WowRuntime.Navigation` | 未实现 | 当前由 `UnavailableNavigationService` 返回 NotImplemented | 不能声称有导航 |
| `SpellFire.RobotManager` | 最小生命周期成品 | 内置 Product 生命周期和契约守卫 | 不加载外部 Product，不代表业务产品体系完成 |
| Product 体系 | 未开始 | 只允许后置设计 | 不兼容官方 wRobot Product |

## 3. 当前硬阻塞：CTM

### 3.1 本仓事实

当前地址表只有：

```text
ClickToMoveType = 0x008A11F4
```

当前没有：

- CTM X/Y/Z 写入模型。
- CTM action 写入模型。
- CTM stop/recovery 写入模型。
- Movement.Go 实现。

当前已有：

- Hook 协议白名单 `ClickToMoveMove = 6`。
- RuntimeHost CLI `ctm-move <pid> <x> <y> <z> [guid] [action] [precision]`。
- Runtime facade `ClickToMoveMove(...)`。
- 安全拒绝语义：native 未接入时返回 `ClickToMoveNativeUnavailable`，不能伪装成功。

### 3.2 wRobot 参考事实

审计结论：

- wRobot 的 `MovementManager.MoveTo` 最终调用 `ClickToMove.CGPlayer_C__ClickToMove(...)`。
- CTM Move 使用 action `4`。
- `0x8A11F4` 是 CTM 状态读取，不是完整移动写入模型。
- wRobot 不是靠宿主侧直接写静态 X/Y/Z 完成移动。

因此 SpellFire_Plus 不能把 CTM 做成：

```text
WriteFloat(X)
WriteFloat(Y)
WriteFloat(Z)
WriteInt(Action)
```

正确方向是：

```text
Hook 主线程桥 -> 白名单 CTM native command -> CGPlayer_C__ClickToMove
```

### 3.3 Well 参考事实

Well 只允许作为地址参考，不允许复用 legacy 注入链。

已知稳定地址：

- `FrameScript__Execute = 0x819210`
- `CGPlayer_C__ClickToMove = 0x727400`
- `CGPlayer_C__ClickToMoveStop = 0x72B3A0`
- `ClickToMoveTypePush = 0x8A11F4`
- `ClickToMoveX = 0x8A1264`
- `ClickToMoveY = 0x8A1268`
- `ClickToMoveZ = 0x8A126C`

限制：

- 不复用 Well/EasyHook。
- 不引入第二套 Hook 主链。
- 不跨回 `SpellFireWPF` 改代码。
